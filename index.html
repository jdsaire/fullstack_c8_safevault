⚙️ Cumulative Defensive Architecture (Activities 1 & 2)

WCAG 2.1 AAA Compliant

1. Input Validation

Enforces strict character sets (^[a-zA-Z0-9_.-]+$), length limits (3–50 chars), and RFC 5322 email constraints before data enters the system.

2. Dual-Stage Sanitization

Strips client-side dangerous tags and applies server-side WebUtility.HtmlEncode so special characters never execute as DOM code.

3. Parameterized Queries

Zero string concatenation in SQL commands. Inputs are bound strictly as literal values via SqliteParameter across intake and login queries.

4. Salted BCrypt Hashing

Passwords are hashed via BCrypt.Net-Next (cost factor 12, unique 128-bit salts) and verified with constant-time anti-enumeration fallbacks.

5. RBAC & Signed Tokens

Enforces Admin, Auditor, and User role policies with HMAC-SHA256 session tokens protecting /api/admin/dashboard and /api/audit/logs.

6. 18 NUnit Security Tests

8 input/SQLi/XSS tests (TestInputValidation) + 10 BCrypt/login/RBAC tests (TestAuthAndRbac) verified against in-memory SQLite.
